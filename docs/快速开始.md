# 快速开始

## 前置条件

- **JDK 25**（本机默认 JAVA_HOME 是 JDK 17，构建前必须切换）：
  ```bash
  export JAVA_HOME="D:\jdk\jdk-25.0.4" && export PATH="/d/jdk/jdk-25.0.4/bin:$PATH"
  ```
- **Summer 4.1.0 已装入本地 Maven 仓库**（源码在 `E:\summer_workspace`，`mvn -s settings.xml clean install -DskipTests`；本机已完成，注意本地装的是含 3 个 bug 修复的版本，升级框架时需重新打补丁）。
- **MySQL**：本机 WSL Docker 容器 `mysql8`（8.0.46），`localhost:3306`，root/root123456，库 `myshop`。

## 构建

```bash
cd myshop-backend
mvn clean install        # 全量构建 + 10 个 H2 端到端冒烟测试
```

## 运行（一体化 jar：API + 门户 + 后台 + 商城）

```bash
# 方式一：脚本
start.bat                # 工作区根目录，双击或执行均可

# 方式二：命令行
java -jar myshop-backend/myshop-manager/myshop-manager-web/target/myshop-manager-boot.jar
```

打开验证：

| 地址 | 内容 |
| --- | --- |
| http://localhost:8080/ | 门户页（两个入口） |
| http://localhost:8080/mall/ | 商城 |
| http://localhost:8080/admin/ | 后台管理 |

数据源配置在 `myshop-manager-web/src/main/resources/application.yml`，可用环境变量覆盖（松弛映射，**不支持** `${VAR:default}` 语法）：`SUMMER_DATASOURCE_URL / _USERNAME / _PASSWORD`。

## 数据库初始化与种子数据

```bash
# 建表（含商城 mall_* 表）
mysql -uroot -proot123456 myshop < myshop-backend/项目文档/myshop-manager.sql

# 商城演示种子（幂等，可重复执行；含 22 个图文匹配商品、9 类别、5 品牌）
docker exec -i mysql8 mysql -uroot -proot123456 --default-character-set=utf8 myshop < myshop-backend/dev/mall-seed.sql
```

## 前端开发模式（热更新，代理到后端 8080）

```bash
# 后台管理（base=/admin/，端口 5173）
cd myshop-manager-ui && npm install && npm run dev   # http://localhost:5173/admin/

# 商城（base=/mall/，端口 5174）
cd myshop-mall-ui && npm install && npm run dev      # http://localhost:5174/mall/
```

同步构建产物到后端（`npm run sync` = build + copy）：

```bash
cd myshop-manager-ui && npm run sync   # dist -> static/admin/
cd myshop-mall-ui && npm run sync      # dist -> static/mall/
```

sync 后需要重新 `mvn -pl myshop-manager/myshop-manager-web package -DskipTests`（或全量 install）刷新 jar 内静态资源。

## 本地一键验证（无 MySQL，H2 MySQL 模式）

```bash
cd myshop-backend/myshop-manager/myshop-manager-web && mvn exec:java -Dexec.mainClass=com.rocket.myshop.ManagerApplication \
  -Dexec.classpathScope=test \
  "-Dsummer.datasource.url=jdbc:h2:mem:myshop;MODE=MySQL;DB_CLOSE_DELAY=-1;INIT=RUNSCRIPT FROM 'file:E:/myshop_workspace/myshop-backend/dev/h2-init.sql'" \
  -Dsummer.datasource.driver-class-name=org.h2.Driver -Dsummer.datasource.username=sa "-Dsummer.datasource.password="
```

说明：

- H2 是 test 依赖，不会打进 boot.jar；boot.jar 生产用 MySQL。
- 连接池每个新连接都会执行 INIT 脚本，故 `dev/h2-init.sql` 的种子部分先删后插（幂等）；mall 表是运行时数据，只建表不删数。
- 冒烟测试（`ManagerSmokeTest`）用自己的内联 H2 Regular 模式 schema，改表结构时三处脚本要同步：`项目文档/myshop-manager.sql`、`dev/h2-init.sql`、测试内 `initH2Schema()`。

## 已知坑位（改代码前必读）

1. Summer `@TableId.value()` 不参与列名解析——主键必须同时标 `@TableId(value="id_")` 和 `@TableField("id_")`。
2. Summer `@RequestParam` 只读查询串，POST 表单体不解析；写接口一律 JSON body 或 `?id=` 查询串。
3. 路由只支持整段 `{var}`；`.json` 后缀模式和裸 `/**` catch-all 均不支持（所以前端走 HashRouter）。
4. MySQL JDBC 对 `TINYINT(1)` 列默认返回 Boolean（tinyInt1isBit）——对应 Integer 字段时列必须用 `TINYINT`（见 mall_order.status_）。
5. 浏览器 fetch 的 GET/HEAD 请求不能携带 body——前端 client.js 已按 method 过滤。
6. 有 `@Transactional`/`@Aspect` 的类不能是 final（Summer 代理要求）。
7. 本机直连 GitHub 超时，git remote 平时指向 gh-proxy.com 镜像；push 时需临时改回 `https://github.com/chinahub/myshop.git`。
